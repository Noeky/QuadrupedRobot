# 基础前行（首版，待实机调试）

仍使用本目录 servo_control.ino 和既定8路接线。当前Arduino窗口会自动读取新增头文件。

## 逻辑

采用四拍爬行，抬腿顺序左前→右后→右前→左后。周期4秒，每腿摆动占20%，其余时间支撑，摆动不重叠。脚相对髋关节向前为+x、向下为+z，默认参考脚位置(0,65)mm，步长28mm、抬脚12mm。摆动脚向前，支撑脚向后，通过40/45mm两连杆逆解换算髋/膝角度，再用各关节站姿和方向映射到servo.write()。每20ms更新，开始和回站姿用1.5秒插值。

这是开环的初始步态，尚未验证实际承重、重心是否落在三足支撑区域、脚底摩擦或实际前行。没有侧摆自由度和姿态反馈，单腿抬起不等于必然稳定。模型假设各腿膝关节朝相同的后弯分支；如果实物前后膝弯曲分支不同，需要修改逆解分支，不能仅靠dir符号修正。舵机命令度数和物理角度比例也需要实测吻合，500～2500μs不保证每只恰好180°。

## 首次配置

串口115200、New Line。先托起机身，检查腿部无顶死。上电沿用原程序全部90°中位，默认不走。即使载入已保存配置也不会自动回站姿或行走。

1. 用原来的`1 90`、`set 2 100`等逐路命令调整**实际站姿**：各脚在髋轴正下方约65mm、膝向后弯，两连杆轴距40/45mm。此时髋相对向下竖直约43.05°向前，膝相对大腿后弯约80.4°，这些是物理几何角，不能直接当成servo.write命令角。按实际安装找到对应八个命令值。
2. 发送`capture`记录当前八个命令值作为站姿基准。它只记录最后命令，不测量舵机位置。
3. 配置每路`dir ID 1`或`dir ID -1`，八路都要设置。髋：命令角增加时，大腿向前转=+1，向后转=-1。膝：命令角增加时，小腿相对大腿向后折、后弯角增加=+1，否则=-1。先在托起状态用站姿±5°确认，再回站姿；不要猜左右镜像符号。
4. `ws`检查站姿与方向；`save`保存到ESP32闪存。重启自动读取，`load`也可读取（不会移动）。手动改变舵臂装配位置后必须重新校准。
5. 发送`stand`缓慢回记录站姿，托起检查，再`f`检查抬腿方向，`stop`立即保持当前命令位置。确认后再在平地扶持机身尝试，尚不能把编译通过当成会稳定行走。

`f`只在站姿已capture、八个方向均设置且舵机均已attach时执行；先检查整个周期命令落在0～180内，超出即拒绝。没有额外的机械工作限位。`f`启动后持续循环，直到`stop`或手动角度命令。拔USB不会自动停止，需切断舵机电源；此版没有无线控制或通信超时停止。

## 命令

|命令|作用|
|---|---|
|`f`|从当前命令位置插值进入步态，然后持续前行|
|`stop`|取消步态和插值，保持最后命令角；不会自动落脚或断电|
|`stand`|停止步态，1.5秒回已记录站姿|
|`capture`|静止时记录当前命令作为站姿|
|`dir 3 -1`|设第3路几何角到命令角的符号|
|`ws`|显示步态、站姿与方向配置|
|`save` / `load`|保存/读取步态校准|
|`1 90` / `set 1 90` / `all 90` / `init`|保留原手动功能，同时停止步态|
|`s` / `list`|接线与最后命令角；不是传感器反馈|

步长、抬脚和参考高度在walk_math.h，周期在walk_control.h。改变参考高度后要重新确定基准站姿。
