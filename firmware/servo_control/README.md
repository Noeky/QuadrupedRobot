# 八舵机控制、手机面板与前进/后退/转向

Arduino IDE打开本目录`servo_control.ino`，保留同目录全部头文件。依赖ESP32开发板包及ESP32Servo；WiFi、WebServer、ESPmDNS、Preferences来自ESP32开发板包。串口仍为115200、New Line。接线以[引脚分配](../../hardware/引脚分配.md)为准，左右按机器人自身判断，超声波支架端为前方。

## 手机连接

1. 烧录此版本后，机器人尝试连接已配置路由器，同时开启`Quadruped-xxxxxx`热点。不会一直等待路由器，串口及主循环仍可运行。
2. 同一Wi-Fi下访问`http://quadruped.local`或串口打印的局域网IP；手机和机器人所在网络必须允许设备互访，访客网络隔离可能阻止访问。
3. 不知道IP或路由器连接失败时，手机直连机器人热点（默认密码`quadrobot`），浏览器输入`http://192.168.4.1`。手机提示无互联网时保持连接。
4. 面板“Wi-Fi与手机连接”可设置路由器名称及密码，保存到板内，重启后沿用；密码不通过状态接口返回。路由器修改只能在停止状态执行，热点仍保留。

可选：将`wifi_config.example.h`复制为`wifi_config.h`填写首次连接信息。后者已被Git忽略，不提交真实密码；已有板内网络配置优先于该文件。热点密码也可在该本地文件调整。面板全部资源由ESP32提供，不依赖互联网或CDN。网页适用于可信局域网，没有互联网远程控制或账号登录功能。

手机可操作：前进、后退、左转、右转、停止、回站姿、速度、转弯增益、末端前后偏移、四腿步态参数、八路调角、全部调角/90°、逐路方向、标定与步态存档、状态和Wi-Fi设置。串口与网页使用相同命令执行器，错误会返回网页；打开页面、刷新状态不会自动运动。

## 速度与逐腿参数

发送 `walk speed 0.5` 可将周期拉长到约8秒，适合观察换撑。发送 `walk deadband 1` 可让行走中的每路目标相对上次下发值累计约1°后再更新，以减少廉价舵机对细小往返命令的反应。死区可在0～5°间调节，0为关闭，重启恢复默认1°。回站姿、手动调角和启动目标仍使用完整精度。

`walk set 腿号 抬脚高度 落脚深度修正 步长 抬脚百分比 放脚百分比` 要一次给齐该腿的五项参数。例如 `walk set 2 18 0 28 25 25` 表示右前腿抬高18mm，其余参数沿用默认值。先 `stop` 再应用，用 `walk` 试走，满意后用 `walk save` 保存四腿参数。

速度为连续数值，输入`0.731`、`1.23`等小数，不是固定档位。当前输入边界为0.05～4倍，周期=4秒/倍率；这些边界只是软件输入限制，不代表各速度都能实机稳定运行。可运动中调速，保持相位连续。仅存内存，重启恢复1倍；1.5秒启动/回站姿插值不随倍率改变。

## 前进、后退与左右转

`walk` 默认前进；`walk back`（或 `back`）使用反向步态；`walk left`/`walk right`（或 `left`/`right`）是带差速的弧线。行走中可直接切换方向，固件以 2/s 的速率平滑改变方向和转向；前进↔后退会经过零步长，不会瞬间反向。转向目标在 1.5 秒启动过渡完成后才生效，过渡期间改向会被拒绝，等过渡结束再发。

后退不是新步态：同一足端轨迹的 x 取反，支撑脚相对机身向前推，机身向后。左/右转也不修改板内 stand、dir 或 LegTuning，不需要重新标定。

转向由左右腿步长差实现：左转时右侧步长变大、左侧变小，右转相反。基础 `stride` 不变，实际每腿步长 = `stride × (1 − turn × direction × side × gain)`，side 为左 +1/右 −1，`turn` 为 +1 左/−1 右，`gain` 默认 0.5。实际步长必须留在 0～50mm 软件包线内，否则预检拒绝；用 `walk turn 0.1..0.8` 降低或提高增益，只能在停止时改，仅存 RAM。默认 28mm 步长配 0.5 增益时左右为 14/42mm。

已在后退中按 `walk left`/`walk right` 时保持后退方向，变成后退弧线；手机页的“左转/右转”按钮同样保持当前前进/后退方向。想保持当前前进/后退方向并取消转向，按“回直行”或发 `walk straight`；想回前进直行，按“开始前行”或发 `walk`。

若实机左右转方向相反，把 `walk_math.h` 的 `TURN_SIGN` 改为 -1 后重新编译；这是唯一的方向翻转点。转向没有偏航/姿态反馈，弧线半径会随地面摩擦、供电和负载变化，不能保证精确轨迹；先低速、小增益试。`stop` 会保持最后姿态，但把下一次启动方向重置为前进直行；这只影响下一次 `walk`，不会改变当前命令角。

## 末端前后偏移（站立与行走统一）

`foot offset MM` 给 `stand` 和所有步态统一加一个前后偏移，单位 mm，范围 -20～20；**负值 = 足端整体后移**，正值前移。它只改 RAM，不改板内存档，停止时才能改。偏移同时作用于回站姿和 `walk`/`walk back`/转向的足端轨迹，所以站立和行走的末端基准一致。

```text
stop
foot offset -3
stand
# 观察偏移后的站姿；再 walk 看轨迹
foot offset 0
stand
```

- 先试 -2～-5mm，一次 1mm 微调；不要直接 -20。
- 偏移会改变支撑多边形相对机身的位置和舵机命令角；如果 `stand` 或 `walk` 报不可达，减小绝对值。
- 只测试就不要 `stand record`/`stand save`；断电重启会清掉偏移，回到板内站姿/步态。

若要把偏移固化到下一次开机：

```text
stop
foot offset -3
stand
# 等站姿稳定后：
stand record     # 记录当前八路命令；记录时会自动把 foot offset 归零，避免叠加
stand save       # 覆盖 quad-walk 的站姿/方向；原值在 calibration_backup.md
```

固化只改站姿/方向，不需要 `walk save`；四腿 lift/depth/stride 仍是原值。`stand record` 捕获的是命令角，不是实测角。

腿编号：1左前、2右前、3左后、4右后；舵机编号仍为1～8，不混用。每条腿独立设置：

|参数|默认值|输入边界|作用|
|---|---:|---:|---|
|抬脚高度|15mm|0～30mm|相对该腿落脚平面向上抬起的距离|
|落脚深度修正|0mm|-10～10mm|步行落脚及支撑高度=65mm+修正；正值向下伸，负值回缩|
|步长|28mm|0～50mm|足端前后行程，范围为±步长/2|
|抬脚时间|25%|10～45%|占单腿摆动时段的比例|
|放脚时间|25%|10～45%|占单腿摆动时段的比例|

抬脚与放脚比例之和不得超过80%，剩余时间用于保持抬脚高度前迈。应用前要求停止步态及插值；固件检查完整轨迹可达性，配置完整时还检查实际标定对应的0～180命令范围。拒绝时不更新任何腿参数，也不会为了应用参数自动驱动舵机。输入边界不是机械限位。

默认`stand`仍直接回当前标定站姿，参考高度65mm，不随逐腿参数改变。落脚深度修正只作用于步行轨迹，并持续到该腿支撑阶段。逐腿步长可辅助修正偏航，但没有姿态反馈，不能保证走直线。

“保存步态”只保存四腿参数，使用独立闪存命名空间`quad-gait`，不会覆盖`quad-walk`中的站姿/方向，也不保存方向、turn gain、speed 或 deadband。开机读取有效步态参数；读取不会运动。保存/读取/恢复默认均须停止。恢复默认只改内存，需再保存才能覆盖原步态备份。Wi-Fi使用独立`quad-net`命名空间。

## 步态与标定原理

`walk` 采用对角步态。**左前＋右后**与**右前＋左后**交替抬脚，每腿摆动与支撑各占周期的一半。换撑时，两组足端轨迹都经过各自的落脚平面。相位安排参考 [Sesame Robot 的前进实现](https://github.com/dorianborian/sesame-robot/blob/main/firmware/movement-sequences.h)，命令角由 R3 自己的逆解和标定计算。

默认摆动前25%抬脚，中50%前迈，后25%落脚。支撑脚后移的首尾各15%逐步加速和减速，中段匀速。控制循环延迟时，单次相位推进最多按40ms计算，因此卡顿期间实际周期可能变长。

40/45mm两连杆逆解，x向前、z向下；参考脚位置为髋轴正下方65mm、小腿后弯分支，参考几何角为髋43.049°、膝80.406°。命令=站姿命令+dir×逆解相对参考变化。不同膝分支不能只靠dir纠正。每约20ms更新，先保留逆解的小数角度，再转换为整数微秒的 PWM 命令。状态中的整数角度为显示值；串口 `s` 同时打印最后下发的脉宽。

50Hz PWM、`attach(pin,500,2500)`；开机先读取已保存的站姿和方向，舵机接入后逐路下发站姿角。没有有效存档时才下发90°。**90°仅为电气中位，不是机械零位或站姿。**500～2500μs不保证每只舵机恰好转180°；没有额外机械工作限位。USB COM号不固定，GPIO16/17此处输出PWM，不同时用于Serial2。

现有闪存站姿/方向无需重新记录站姿，不自动覆盖标定。需要重新标定时托住机身、小幅逐路调整，令各脚位于髋下约65mm且膝分支一致；`stand record` 记录八路最后命令到内存，用 `stand direction` 设置全部方向后，`stand save` 写入闪存。捕获和设置方向只修改当前标定，断电前需保存。`stand load` 在停止时载入已保存标定；另发 `stand` 才回到当前标定站姿。

本组实测1路命令增加时大腿向后；结合CAD左右镜像及轴向推导dir为：**-1、+1、+1、-1、-1、+1、+1、-1**。用户反馈看上去正确，其余7路没有逐路实测记录；这些值在板内，不是固件默认值。髋正方向为大腿前摆，膝正方向为小腿相对大腿后弯增加。

## 运行与存档

- **运行**用 `walk`、`walk back`、`walk left`、`walk right`、`stop`、`stand`、`walk speed` 和 `walk turn`。
- **标定**先调角摆出站姿，再用 `stand record` 记录八路命令角，用 `stand direction` 设置各关节方向，最后用 `stand save` 保存整套标定。
- **步态**用 `walk set` 应用每条腿的参数。试走后可用 `walk save` 保存当前已应用的四腿参数。用 `walk load` 恢复存档，或用 `walk reset` 把当前参数恢复为默认值。
- **方向**前进/后退/左右转是运行时状态；`walk turn` 只改 RAM 的差速增益，重启回 0.5，不属于 `walk save` 的内容。

标定和步态各有独立存档，保存与载入在停止时进行。载入替换对应的当前设置。固件可以读取旧版存档。手机面板分别在步态参数和标定区域提供对应操作。

## 全部串口指令（网页有对应操作）

每行一条、小写；角度0～180整数，舵机编号1～8。

|指令|功能|
|---|---|
|`walk`|预检对角步态，1.5秒进入步态并持续前行；已行走时回到前进直行|
|`walk straight` / `straight`|取消转向，保持当前前进/后退方向；停止时从前进直行启动|
|`walk back` / `back`|反向步态；可从停止启动，也可在行走中平滑切换|
|`walk left` / `left`|左转弧线；停止时从前进左转启动，后退中保持后退方向|
|`walk right` / `right`|右转弧线；同上|
|`walk turn 0.5`|转向差速增益0～0.8，默认0.5；停止时应用，仅RAM|
|`foot offset -3`|站立和步态足端统一前后偏移，mm，-20～20，负=后移；停止时应用，仅RAM|
|`stop`|取消步态及插值，保持最后命令，不落脚、不断电；下一次启动方向重置为前进直行|
|`stand`|1.5秒回当前标定站姿|
|`walk speed 0.731`|任意小数速度倍率，当前边界0.05～4|
|`walk deadband 1`|最小舵机命令变化，单位为命令角度，可设0～5，默认1|
|`walk set 3 18 2 27 20 35`|左后腿：抬18mm、深度修正+2mm、步长27mm、抬脚20%、放脚35%；停止时应用|
|`walk save` / `walk load` / `walk reset`|保存/读取步态或恢复默认内存步态，不改标定/方向/turn gain|
|`1 90` / `set 1 90`|调第1路，同时停止步态|
|`all 90` / `init`|全部调角/回90°，停止步态，不清标定|
|`stand record`|静止时捕获八路当前命令为站姿，仅内存|
|`stand direction 1 -1`|停止时将第1路方向设为-1（只能±1）|
|`stand save`|停止且站姿、方向、attach完整时保存标定|
|`stand load`|停止时载入标定|
|`s` / `list`|接线、attach和最后命令角|
|`ws`|标定、方向、motion/转向、foot offset、速度、四腿参数及配置状态|
|`h` / `help`|帮助|

已有前进、后退、左转、右转；仍没有姿态反馈、足底接触反馈或自动避障。转向是开环差速，不保证直线或固定半径。HC-SR04尚未配置接线及测距控制。单独`90`或`+`不是有效命令。

## 手机掉线与停止

手机在持有控制权时用一次心跳请求同时读取状态。页面区分“指令未获确认”和“指令已确认，状态未刷新”。前者表示手机没收到应答，机器人可能已执行；先核对运动状态，必要时发 `stop`。后台状态读取失败时，连接标签会显示异常。

手机控制页面每约700ms发送心跳；正常主循环下超过2.5秒未收到控制页面心跳，停止步态/插值并保持最后命令。切到后台尝试立即stop，关闭网页或掉线通过超时处理，恢复连接不会自动重新行走。同步HTTP处理可能延迟超时检查，这不是硬实时急停。

一个页面持有控制时，其他页面不能直接修改参数或发起运动，但可以停止。只读刷新不续接另一页面的控制权。成功的串口修改命令接管控制，串口启动步态仍无通信超时停止；网页轮询不会为串口行走自动启用心跳。停止不等于断电，拔USB也不保证舵机电源关闭。

## 验证和实机状态

手机 Wi-Fi 控制、逐腿调参、前进/后退/左右转已加入固件。实机前进仍不稳定；转向和倒退是开环差速/反向步态，需要低速、小增益逐步验证。传感器尚未接线；后续接入 IMU/测距后再做闭环。

本机检查：实际数学头文件40,004个默认腿样本、1,001个摆动样本；1,728,864个逐腿参数组合样本检查可达性、正逆解、连续性、支撑平面及摆动高度；默认最大髋/膝相对变化约29.451°/27.804°。新增检查覆盖后退镜像（x 取反、z 不变）、左转差速的有效步长和 `validTurn` 上限。`test_phone_control.cpp`将实际固件与HTTP处理器编译到主机，用硬件替身测试前进/后退/左右转命令、turn gain 限制、参数拒绝、闪存隔离、控制权和超时；替身不会访问真实串口、Wi-Fi适配器、闪存或舵机。浏览器页面使用模拟API检查手机布局和交互，不代表ESP32无线链路已实测。

```powershell
arduino-cli compile --jobs 4 --fqbn esp32:esp32:esp32 firmware/servo_control
g++ -std=c++11 scripts/test_walk_math.cpp -o .cad_runtime/test_walk_math.exe
./.cad_runtime/test_walk_math.exe
g++ -std=c++11 -Iscripts/test_support scripts/test_phone_control.cpp -o .cad_runtime/test_phone_control.exe
./.cad_runtime/test_phone_control.exe
```

CAD、数学及软件检查不验证实体干涉、舵臂滑移、供电、承重或行走稳定性。没有侧摆关节或重心迁移控制，单腿抬起也不保证三足支撑稳定。托住机身逐步试验；持续嗡鸣、顶死或倾倒时停止并视情况切断舵机电源。
